
## tools/ (Task C) — provisioning, ARM bridge, V-Flash

Committed `c033cb8` (pushed to origin/main). 137 pytest tests, all real
artifacts, no mocks. Run with `/usr/bin/python3 -m pytest tools/tests -q`
(`/usr/local/bin/python3` has no pytest).

Hard-won root causes (each one cost a debugging cycle):
- **`debugfs set_inode_field <f> mode N` writes the WHOLE st_mode.** Setting
  only permission bits (e.g. 0600) clears the file-type bits, so the inode
  becomes "bad type" and the next `e2fsck` DELETES the entry. `chmod` must OR
  in the type bits (0o100000 regular, 0o040000 dir, 0o120000 symlink, ...).
  Symptom: files written fine, then vanish after a flush; `/build.prop` showed
  inode 0 in `debugfs ls /`.
- **debugfs never updates the superblock free-block/free-inode counters.** Any
  write batch must be followed by `e2fsck -fy` (implemented as
  `Ext4Image.flush()`, auto-called on context exit). Without it, fsck reports
  "Free blocks count wrong".
- **`unsquashfs -d <dir>` fails if the parent of `<dir>` is missing** — it does
  not create intermediate dirs. `unpack_squashfs` must `os.makedirs(workdir)`.
- **Nested vs flat prebuilt layouts collide.** Fetching
  `prebuilts/lib64/libndk_translation.so` and `prebuilts/lib/…` into one flat
  dir overwrites the 64-bit lib with the 32-bit one. Preserve the remote
  sub-path in the cache; resolve with a nested-then-flat lookup.
- **Edify args must split on top-level commas**, not by scanning for quotes:
  `set_perm(0, 0, 0755, "/p")` loses its numeric args otherwise and indices
  shift (mode read from args[0] instead of args[2]).
- **A stub `updater-script` is not authoritative.** Magisk ships a no-op edify
  script plus a shell `update-binary`; fall through to the next strategy when
  the edify pass applies zero actions.

Environment: `mksquashfs`/`unsquashfs`/`xorriso`/`e2fsprogs`/`qemu-img`/
`img2simg` all present. Loop/mount still unusable — offline editing via debugfs
is the only route, which is why the fsck step is mandatory.

Real-image validation: Android-x86 9.0-r2 `system.img` at
`/workspace/vap-cache/sfs_out/system.img` — inject (22 proxy libs, 5 core
files) and Magisk flash both leave an e2fsck-clean fs; qcow2 round-trip
preserves edits and `qemu-img check` reports no errors.

## Task D — V-Flash + ROM Manager in the Qt UI (2026-11-12)

- New: `ui/tools/ToolRunner.{h,cpp}` (async QProcess wrapper for the
  `tools/` CLIs + static parsers), `ui/ui/VFlashDialog.{h,cpp}`,
  `ui/ui/RomManagerDialog.{h,cpp}`, `ui/tests/test_provisioning.cpp`.
- **`ui/ui/MainWindow.ui` sets `objectName` explicitly on every sidebar
  button** (shared `secondaryButton` / `ghostButton` QSS id). Consequence:
  `findChild<QPushButton*>("vflashButton")` returns **nullptr** — look up by
  `text()` instead. The generated `ui_*.h` member (`ui->vflashButton`) is
  still correct because the `.ui` field name is independent of objectName.
- CLI contracts verified against the tools: `vflash --image X --inspect |
  --flash PKG [--backup B] | --cat PATH`; `fetch_image --image KEY --out O
  [--iso PATH] [--data-disk P --data-size SZ]`; `inject_arm --image X
  [--profile P | --no-spoof]`.
- `vflash --flash`/`--cat` map the image root onto **`/system`**: an edify
  `package_extract_file(...,"/system/bin/x")` lands at `/bin/x` in the fs.
  (Test had to use `/bin/hello.txt`.)
- `vflash` flash summary line is `actions: N (M applied)`; assert on
  "applied", not on file names.
- Android 7.1-r5 preset added to `tools/vaplayer_tools/image.py`
  (`android-x86-7.1`). `fetch_image.py --list` now shows 4 images.
- Tests: ui ctest 4/4 (new `provisioning` suite = 16 cases incl. a real
  end-to-end flash of an mke2fs ext4 image); tools pytest **138 passed**.
- Builds warning-free under `-Wall -Wextra`.

## Task E finished — quick controls, drag&drop, shared folder, keymapper
Commit `2571ab8` (was `d371faf` before the co-author amend) on `main`.
Files: 16 new + 11 modified; ~3400 LOC of new UI/keymapper/test code.

Two bugs found while reviewing my own Task E code:
1. `onKeymapperToggled` used `dialog.exec()` — a **modal** dialog blocks the
   viewport, so tap-point placement (which happens by clicking the overlay)
   could never work. Switched to a persistent modeless `m_keymapperDialog`.
2. `persistActiveKeymap()` was defined but never called → keymap edits were
   lost on exit. Now called from `closeEvent`.
Also wired mouse → keymapper (`ViewportWidget::mousePressed/Released/Moved`),
which the overlay/engine already supported but nothing fed.

Test additions: `viewportForwardsMouseOnlyWithAnEngine` (inert without engine,
delta only while a button is held). Fixed 4 `QMouseEvent` deprecation warnings
by passing `localPos` as well as `scenePos`.
